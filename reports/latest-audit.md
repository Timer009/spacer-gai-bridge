## 2.2 游戏主循环与状态管理

### 主循环 `frame()` L2095–L2107

- 固定步长 `FIXED = 1/120` 秒。
- 累加器 `acc`，单帧最多补 12 步。
- 帧间隔 `dt` 上限 0.1 秒（防止切标签页后爆步）。
- `paused` 时跳过 `update` 但继续 `render`。

### 状态机 `update()` L910–L960

| 状态 | 行为 |
|---|---|
| `title` | 相机横向巡航，展示地形与世界 |
| `map` | 相机缓慢平移，绘制太阳系航线图 |
| `levelIntro` | 相机跟随，倒计时 1.2s 后进入 `playing`（面板开着则自动暂停） |
| `playing` | `physics(dt)` + `camFollow(dt)` |
| `landed` | 移动平台跟随 + 1.8s 后回航线图 |
| `crashed` | 1.7s 后有余命则重生（`levelIntro` 0.8s），否则 `gameover` |
| `gameover` | 等待按键回航线图 |

### 计时

- 单一全局 `time` 只增不减，贯穿风相位、间歇泉相位、平台漂移、闪烁动画。
- 关卡切换不重置 `time`（相位连续，属有意设计）。

### 暂停

- `paused` 仅作用于 `playing` 状态。
- 打开设置面板会自动暂停，关闭时恢复。

## 2.3 飞船物理、姿态、燃料与环境力

### `physics()` L821–L887

- 转速 `ROT = 3.6 rad/s`（L75）。
- 姿态：`keys.left / keys.right` 直接增减 `ship.a`。
- 推力：`S.thrust`（默认 44），沿机头方向 `sin(a) / -cos(a)`。
- 燃料：`S.burn`（默认 6/秒），与推力同时消耗。
- `ship.flame` 指数平滑（L828），驱动尾焰长度与引擎滤波频率，避免突变。
- 积分：半隐式欧拉，先加速度后位置（L840–L841），帧率无关。

### 边界处理

- 水平钳制 `[24, WORLD_W-24]`，半速反弹（L850–L851）。
- `y < -700` 钳制并清零上升速度（L852）。
- 木星关 `y > 1750` 直接判「坠入云层」（L853）。
- 火卫一离天体 `> 5400` 重置位置并提示（L844–L848）。

### 环境力 `envForces()` L598–L618（物理与预测共用）

- 点质量引力：`levelDef.GM`，`r²` 衰减，半径下限 `0.85R`。
- 均匀重力：`levelDef.g`。
- 风：`windAt(t)`。
- 沙尘暴：爆发期横向脉冲，方向按周期奇偶翻转。
- 大气阻力：速度乘 `exp(-drag*dt)`。
- 间歇泉：喷发期在柱体内按横向距离衰减上推。

### 风模型 `windAt()` L588–L597

- `base + gust*sin(t*0.55)`。
- `stormCycle` 时按 16s 周期分三段倍率 `0.3 / 0.6 / 1.0`。

### 可调参数 `S_DEF / S` L80–L84

字段：

```text
gScale, thrust, burn, vyMax, vxMax, padW, spawnH, lives,
trail, unlockAll, shake
```

持久化键：`vl_cfg`。

## 2.4 碰撞检测、着陆判定与移动平台

### 碰撞几何

| 项 | 位置 | 说明 |
|---|---|---|
| `HULL` | L572 | 7 点闭合外形（绘制与碎片） |
| `SHIP_PTS` | L573 | 7 点采样（碰撞判定） |

> 历史缺陷：此处曾出现“返回数组而非对象导致 `p.x/p.y` 为 `undefined`、所有接触判定静默失效”的严重问题，现已修复。任何改动都必须保持返回 `{x,y}` 对象。

### 接触判定 `checkContact()` L649–L692

- `planetoid` 分支 L651–L661：
  - 点到圆心距离 `<= R`；
  - 角度落在弧内视作平台。
- `float` 分支 L662–L671：
  - AABB 带状判定 `p.y ∈ [pd.y, pd.y+16]`；
  - `ship.vy < -3` 判「撞上平台底部」。
- `terrain` 分支 L672–L691：
  - 先判漂移平台（冰筏）L673–L682；
  - 再判地形高程 `p.y >= heightAt(p.x)` L683–L690；
  - 静态平台匹配采用 `pads.find(... ±3)`。

### 着陆判定 `judgeLanding()` L693–L732

通过条件：

```text
pad 存在
&& 姿态对齐 align >= ALIGN_MIN (0.82，约 35°)
&& ship.vy <= S.vyMax (默认 36)
&& |ship.vx| <= S.vxMax (默认 26)
```

成功处理：

- 行星：沿径向吸附到 `R+9`。
- 移动平台：记录 `landPad` 与 `landOff`，后续跟随。
- 静态平台：吸附到 `pad.y - 9`。
- 得分：`400*m + fuel*5 + max(0, (50-spd)*8)`。
- 星级：`1 + (燃料>=35%) + (spd<=20)`，范围 1..3。
- 推进 `progress.unlocked`。
- 统计 `stats.landings / stats.perfects`。

失败处理：按原因分派文案。

```text
偏离着陆平台 / 着陆姿态过斜 / 下降速度过快 / 横向速度过大
```

## 2.5 轨迹预测系统

### `computePrediction()` L621–L646

- 从当前状态拷贝 `sim` 对象。
- 固定当前朝向 `a`（不预测旋转）。
- 若正在推力则假设恒定推力。
- 步长 `1/40`，160 步 = 4 秒视距。
- 每 5 步采样一次绘制点。
- 与真实物理共享 `envForces()`，因此风/阻力/间歇泉/尘暴都一致。
- 移动平台按预测时刻 `t` 取 `padCX`（L639），木星/木卫二预测准确。

终止条件：

| 类型 | 条件 |
|---|---|
| `planetoid` | 与圆心距离 `<= R-2` |
| `float` | `y > 1750` 或进入平台带 `[pd.y, pd.y+12]` |
| `terrain` | `heightAt(x) <= y` |

### 绘制 `drawPrediction()` L1526–L1547

- 绿色点列 + 红色叉号撞击点。
- 冥王星 `predNoise` 时点列抖动、撞击点闪烁。

# 第三部分 新增玩法可行性评估

## 3.1 Ocean Recovery（海上移动平台火箭回收）

### 可直接复用

- 移动平台运动模型：`padCX/padY` L498–L506，着陆跟随 L942–L945。
- 移动平台着陆分支：`judgeLanding` L702–L704（`landOff` 已实现）。
- 船体视觉：`drawRaft` L1213–L1252 本身就是「小船」造型。
- 水花粒子：`spawnDust` 与通用粒子系统 L769、L802。
- 风与阻力：`windAt / envForces` L588–L618。

### 必须新增

- 水面：正弦波形 + 水面渲染（可与地形共存，`sea{y, amp, k}`）。
- 危险判定：入水即坠毁，预测线也要在水面终止。
- 起伏平台：`padY` 需支持 `p.bob`（`baseY + sin(t*w+phase)*amp`）。
- 溅落特效与入水音效。

### 关键设计陷阱（唯一真正的技术难点）

平台上下起伏时，着陆判定必须使用相对速度：

```text
relVy = ship.vy - padVy
```

否则平台上升瞬间会把公平着陆判成「下降过快」，或反之放行高速撞击。

### 工作量评估

S（约 80–150 行）。

## 3.2 Tower Catch（发射塔机械臂捕获火箭）

### 可直接复用

- 接触判定骨架：`checkContact` 的 terrain 分支与岩柱三角判定 L861–L873。
- 成功结算：`judgeLanding` L693–L732 的计分/星级/推进/统计（建议抽出复用）。
- 特效：粒子、尘土、震动、音效。

### 必须新增

- 塔体几何（竖直结构 + 两条可动机械臂）+ 捕获区 AABB。
- 独立判定阈值：现有 `ALIGN>=0.82 / vy<=36 / |vx|<=26` 对「机械臂夹住」过宽。
  - 建议：`|vx| <= 2`，`vy ∈ [-2, 12]`，机身在捕获框内。
- 机械臂动画（时间驱动，纯渲染）+ 捕获后合拢表现。
- 塔体碰撞即毁（复用岩柱逻辑）。

### 风险

捕获成功后飞船应「挂住」而非「落地」，需要 `landed` 状态增加 `caught` 变体，或新增 `caught` 状态，否则相机/跟随/结束流程要复制一遍。

### 工作量评估

M（约 120–200 行）。

### 建议方案（皮肤注册表，最小侵入）

```js
SKINS = {
  classic : { hull:[...], pts:[...], flameY:9,  scale:1.0, draw(...) },
  f9      : { ... , scale:1.35 },
  sh      : { ... , scale:1.7  }
}
```

- `shipWorldPts()` 改读 `SKIN.pts`（碰撞点需加密，细长体 7 点会漏检）。
- `drawShip()` 调 `SKIN.draw()`，尾焰锚点用 `SKIN.flameY`。
- `explode()` 用 `SKIN.hull` 分段。
- `ship.a` 语义不变（机头朝 `-y`），着陆对齐逻辑无需改。

### 关键取舍

真实比例（F9 约 70m、SH 约 120m）在现有 26 单位船体尺度下会大 3–5 倍，直接影响平台宽度、燃料、阈值平衡。

建议保持「视觉高度基本一致，只改轮廓与细节」，`scale` 控制在 1.0–1.7，仅做观感差异，避免十关平衡全盘重调。

### 工作量评估

M。

# 审计结论

架构清晰，「物理与轨迹预测同源」是最大优点，避免了预测线与实际飞行不一致。

当前最主要的问题三项：

- **P0-1**：解锁校验缺失（已运行时复现，锁定关卡可直接进入）。
- **P1-1**：陨石渲染缺 `r` 字段（只剩拖尾线）。
- **P1-2**：仓库代理配置失效，导致无法推送。

其余为一致性/体验级问题。

两个新玩法都能在现有移动平台与结算框架上低成本扩展。

最大技术难点：

- 起伏平台的相对速度判定。
- 皮肤化后的碰撞几何精度。

本次审计未做任何修改，工作区仍为 `526397a` 干净状态。
